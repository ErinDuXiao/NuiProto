# ぬいぐるみクレーン + 棚 MVP 設計書

- 日付: 2026-09-03
- ステータス: 設計確定
- 依頼元: 「Webクレーンゲーム＋ぬいぐるみ棚 MVP 開発依頼書」

## 1. 目的

検証したい問いは一つ。

> **ぬいぐるみを獲得し、棚に持ち帰ったときに愛着が生まれるか。**

この設計書のあらゆる判断は「愛着が生まれるか」に従属する。クレーンの物理的リアリティ、
コンテンツ量、技術的高度さは、この問いに寄与しない限り価値を持たない。

プレイヤーに「この子を取った」ではなく「**この子を家に連れて帰った**」と感じさせる。

- クレーン = 入手方法
- 棚 = 生活する場所
- ぬいぐるみ同士の関係 = 感情的報酬

## 2. スコープ

### 作るもの

1. My Shelf 画面（自由配置・保存・環境アニメーション・シェア）
2. Crane Game 画面（擬似3D自作物理・見守りぬいぐるみ）
3. 出会いの演出（Priority 1）
4. シェア（PNG生成 → Web Share API → クリップボード）
5. プレイログ（JSON出力）
6. Developer Menu

### 作らないもの

依頼書 21 章の全項目（ユーザー登録、バックエンド、課金、広告、フレンド、チャット、
ランキング、PvP、**交換**、マーケット、トレード、NFT、大量の家具、大量のステージ、
本格ストーリー、ガチャ）。

加えて本 MVP では以下も作らない。

- リアルなアーム弾性・ワイヤー物理
- 複数ステージ／日替わり景品テーブル
- 家具・部屋の拡張
- i18n 機構（日本語固定。英語ワンポイントはリテラル）

## 3. 技術構成

| 項目 | 選択 |
|---|---|
| 言語 | TypeScript (strict) |
| UI | React 18 |
| ビルド | Vite |
| 物理 | 自作簡易ソルバ（外部エンジンなし） |
| 描画 | SVG（全画面共通） |
| 状態管理 | `useSyncExternalStore` ベースの自作ストア |
| 永続化 | localStorage |
| 音 | WebAudio API による生成音（音声アセットなし） |
| テスト | Vitest |

外部ランタイム依存は React / ReactDOM のみ。画像・音声アセットはゼロ。

### 3.1 なぜ自作物理か

Matter.js 等は「転がる・ぶつかる」は得意だが、本 MVP が必要とするのは
**「ちゃんと取れるが、少し転がる」という感情曲線の制御**である。
剛体ソルバの上でこれを実現するには拘束とチューニングに多大な時間を要し、
依頼書 27 章「クレーンの高度な物理表現に時間を使いすぎないでください」に反する。
球体のみを扱う 200 行程度のソルバなら、掴み・落下・出口誘導のパラメータを
直接数値で制御できる。

### 3.2 なぜ全画面 SVG か

ぬいぐるみ描画を単一コンポーネントに統一できる。結果として

- 棚での生活感（13 章）と見守り演出（8 章）が同一の部品で実装される
- シェア画像が、棚 DOM をスタンドアロン SVG に直列化して canvas に流すだけで生成でき、
  html2canvas 等の依存が不要になる
- 新種追加がデータ 1 オブジェクトで完結する（23 章）

## 5. データモデル

### 5.1 Plush 定義（静的データ）

```ts
type Rarity = "common" | "rare" | "special";

type PlushDef = {
  id: string;              // "bear_01"
  name: string;            // "ブラウンベア"
  series: string;          // "forest_friends"
  rarity: Rarity;
  size: number;            // 描画・当たり判定の基準半径 (px)
  weight: number;          // 掴み保持のしにくさ 0.5-1.5
  softness: number;        // 変形量・掴まれやすさ 0-1
  art: PlushArt;           // 見た目パラメータ
};

type PlushArt = {
  body: string;            // 本体色
  accent: string;          // 耳内・腹などの色
  shape: "round" | "pear" | "long" | "blob";
  ears: "round" | "long" | "pointed" | "none";
  extras?: ("beak" | "tentacles" | "flipper" | "tail")[];
};
```

新種の追加はこのオブジェクトを 1 つ足すだけで完了する。IP コラボ時も
コード変更なしでデータとパラメータの追加のみで拡張できる。

### 5.2 収録ぬいぐるみ（10 種）

**Forest Friends**: Bear(common) / Rabbit(common) / Fox(rare) / Frog(common) / Deer(special)

**Ocean Friends**: Seal(common) / Octopus(rare) / Duck(common) / Jellyfish(rare) / Penguin(special)

初期所持は Bear。初回クレーンの主景品は Rabbit（size 大きめ・softness 高めで最も掴みやすい）。

### 5.3 永続スキーマ

```ts
type OwnedPlush = {
  uid: string;             // 個体 ID
  defId: string;           // PlushDef.id
  acquiredAt: number;      // epoch ms
  x: number;               // 棚上の水平位置
  shelfRow: number;        // 0-2
};

type CraneBoardSave = {
  prizes: { defId: string; x: number; y: number; z: number }[];
  attemptsOnBoard: number;   // 現在の盤面での試行回数（アシスト算出用）
};

type SaveV1 = {
  version: 1;
  sessionCount: number;
  owned: OwnedPlush[];               // 配置は OwnedPlush が保持する
  craneBoard: CraneBoardSave | null; // 盤面の途中状態
  attempts: number;                  // 通算プレイ回数
  log: LogEvent[];                   // 上限 2000 件のリングバッファ
};
```

`version` 不一致・パース失敗時は初期状態にフォールバックし、破損データは破棄する。
サイレントに壊れた状態で起動しないこと。

## 6. ぬいぐるみ描画とポーズ

```ts
type Pose = {
  squash: number;    // 1.0 = 通常, <1 潰れ, >1 伸び
  tilt: number;      // 傾き (deg)
  eyeOpen: number;   // 0-1 (瞬き)
  lookAt: number;    // -1(左) .. 0(正面) .. 1(右)
  armRaise: number;  // 0-1 (万歳)
  hop: number;       // 縦オフセット (px)
};
```

`PlushSVG` は `PlushDef` と `Pose` のみを受け取る純粋関数コンポーネント。
状態を持たず、棚・見守り・クレーン盤面のすべてで同一のものを使う。

### 6.1 棚での生活感（13 章）

`useAmbientLife` が以下を全個体に付与する。

- 呼吸: 2.4〜3.2 秒周期の微小な squash（個体ごとに位相をずらす）
- 瞬き: 3〜7 秒のランダム間隔で eyeOpen を 80ms 落とす
- 隣を見る: 12〜20 秒に一度、隣接個体が居れば lookAt をその方向へ 1.5 秒
- クリック: squash 0.85 → オーバーシュートで復帰、短いセリフを表示

静物にしないこと。棚を眺めているだけで何かが動いている状態を保つ。

## 7. クレーンゲーム

### 7.1 座標系と投影

景品は `{x, y, z}` を持つ球。y が高さ、z が奥行き。

```
screenX = originX + x + z * 0.35
screenY = originY - z * 0.55 - y
scale   = 1 - z * 0.0012        // 奥ほどわずかに小さく
```

描画順は z の降順（奥から手前へ）。

### 7.2 物理ソルバ (`physics.ts`)

球体のみを扱う。

- 重力 y 方向
- 床反発 0.35、床摩擦 0.86
- 球同士は水平方向の押し出し（位置補正 + 速度交換、反発 0.4）
- 壁クランプ
- 回転は水平速度から擬似的に導出（見た目用、物理には影響しない）
- 出口穴: 手前中央の矩形領域。中心が領域内かつ下向き速度なら落下 → 獲得

積分は固定タイムステップ 1/120 秒、描画は rAF。

### 7.3 操作（2 段階ボタン式）

```
待機 → [横移動: 長押しで左右] → 決定 →
       [奥移動: 長押しで前後] → 決定 →
       自動: 下降 → 掴む → 上昇 → 出口へ移動 → 開放
```

長押しで移動、離す or 決定ボタンで確定。移動中に画面端で自動反転はしない。
操作説明は画面上に常時 1 行だけ表示する（「長押しで移動、はなすと止まる」）。

### 7.4 掴みと落下

アーム接地時、最も近い景品との水平距離 d から保持力を決める。

```
hold = clamp( (grabRadius - d) / grabRadius, 0, 1 )
     * (0.6 + 0.4 * softness)
     / weight
     * assist(attemptIndex)
```

上昇中は毎フレーム hold を減衰させ、揺れを加える。
`hold < 0.15` で開放 → 落下。

**落下時は必ず出口方向への水平インパルスを与える。** これにより失敗しても盤面が前進する。

```
落下 → 出口へ 20〜60px 近づく → 次回はより掴みやすい
```

### 7.5 アシスト設計（7 章 成功率）

確率抽選は行わない。試行回数に応じて連続的にアシストを強める。

| 試行 | assist | 体感 |
|---|---|---|
| 1 | 0.62 | 掴めるが途中で落ちやすい |
| 2 | 0.78 | 惜しい／取れることもある |
| 3 | 0.92 | ほぼ取れる |
| 4+ | 1.05 | 取れる |

加えて

- 出口から 60px 以内の景品はアームが触れるだけで転落し得る
- 完全な空振り時もアームは最近傍の景品を必ず小突く（「何も起きない」の禁止）

目標: 初見で 2〜4 回以内に 1 匹。上手ければ 1 回。
検証は Vitest で 1000 試行のシミュレーションを回し、
「4 回以内獲得率 >= 0.95」「1 回目獲得率 0.15〜0.45」を回帰テストとする。

### 7.6 見守りぬいぐるみ（8 章）

所持ぬいぐるみから 1 匹（既定では最初の 1 匹）を盤面手前に表示する。
状態機械で Pose とセリフを駆動する。

| 状態 | 表現 | セリフ例 |
|---|---|---|
| idle | ゆるい呼吸、アームを目で追う | 「あの子、気になる。」 |
| aiming | 目を大きく、身を乗り出す、左右に揺れる | 「そこ……！」 |
| dropping | 静止、瞬きを止める | （無言） |
| grabbed | 大きく跳ねる | 「きた！」 |
| missed | のけぞる、すぐ持ち直す | 「あっ！」 |
| nearExit | 前のめり | 「もうちょっとかも。」 |
| success | ジャンプ + 万歳 + 粒子 | 「やった！」 |

`missed` は 0.8 秒で idle に戻し、悲しみを引きずらせない。
クエスト化する台詞（「〇〇を取ってきて」）は入れない。

## 8. 出会いの演出（Priority 1）

獲得後、棚へ戻った直後に `MeetingCeremony` が操作をロックして再生する。
この演出は自由配置ロジックと混ぜず、独立したコンポーネントで管理する。

```
t=0.0  新入りが上から落ちて「ころん」と着地（squash 0.7 → 復帰）
t=0.6  先輩が新入りの方を向く（lookAt 補間）
t=1.0  先輩「はじめまして！」
t=1.8  新入りが 2 回跳ねる／粒子 3 つ
t=2.6  2 匹が並んで落ち着く
t=3.2  小さく "Welcome home."
t=4.0  演出終了 → 配置操作を解放、新入りに 2 秒だけ淡いリング
```

「GET!!!」のような強い演出、レアリティの誇張演出、金色、宝箱は使わない。
成功の温度感は "Welcome home." に揃える。

3 匹目以降も同じ演出を行う。向く先輩は新入りの最近傍 1 匹とする。

## 9. 棚の配置（14 章）

- 3 段の棚板。各段の上面ラインに吸着（縦は自動、横は自由）
- ポインタイベント（マウス・タッチ共通）でドラッグ
- ドロップ時に重なりを検出し、水平方向へ押し出して解消
- 棚の外へは出せない。段をまたぐ移動は可能
- 配置は移動確定時に保存

## 10. シェア（17 章）

優先順に試行する。

1. 棚 SVG を直列化 → Blob → `<img>` → canvas → PNG（1080x1080）
2. `navigator.share` が使え、ファイル共有に対応していれば Web Share API
3. 非対応時はクリップボードへコピー、それも不可ならダウンロード

画像に載せるのは棚・ぬいぐるみ・小さなゲーム名・所持数のみ。広告やロゴは載せない。

将来 `example.com/shelf/xxxxx` を実装できるよう、棚状態をシリアライズする関数
`encodeShelf(state): string` を切り出しておく。
MVP ではこの文字列を URL には使わないが、境界だけ先に作る。

## 11. プレイログ（24 章）

```ts
type LogEvent = {
  type: "session_start" | "shelf_view" | "arcade_enter" | "crane_start"
      | "crane_drop" | "plush_grabbed" | "plush_dropped" | "plush_moved"
      | "plush_won" | "shelf_return" | "plush_placed" | "plush_repositioned"
      | "share_clicked";
  t: number;              // epoch ms
  sessionId: string;
  plushId?: string;
  attempt?: number;
  meta?: Record<string, number | string>;
};
```

上限 2000 件のリングバッファ。Developer Menu から JSON ダウンロード。

## 12. Developer Menu（25 章）

起動: 棚画面右下の小さなドットを 3 回タップ、または `Ctrl+Shift+D`。

機能: 所持品リセット / localStorage 全消去 / 任意ぬいぐるみ追加 /
クレーン景品再配置 / 全シリーズ表示 / プレイログ DL / FPS 表示 /
物理デバッグ表示（当たり判定・速度ベクトル・出口領域）。

## 13. 音（19 章）

WebAudio でその場生成。初回タップで AudioContext を初期化する。

| 音 | 生成方法 |
|---|---|
| クレーン移動 | 低音ノコギリ + ローパス、ループ |
| アーム下降 | 下降するサイン波 |
| 接触 | 短いノイズバースト |
| **ころん** | 木質の 2 連ソフトアタック（帯域 300-800Hz、減衰 120ms）— 最も作り込む |
| 成功 | 3 音の柔らかいアルペジオ |
| 棚に置く | 布のような低いサム音 |

ミュートトグルを常設する。

## 14. アートディレクション（18 章）

- 生成り・淡いウッド・くすんだパステル。彩度は低め
- 角丸を大きく、影は柔らかく薄く
- フォントは日本語システムフォントスタック、字間はやや広め
- 通知バッジ、赤丸、金色、カジノ的表現は使わない
- 日本語 UI ＋ 獲得時のみ英語ワンポイント

## 15. テスト方針

Vitest で以下を回帰テストする。

1. **難易度**: 1000 試行シミュレーションで 4 回以内獲得率 >= 0.95
2. **盤面前進**: 掴み失敗時、景品と出口の距離が必ず縮む
3. **保存**: 保存 → 読込の往復で状態が一致する。破損データで初期化される
4. **配置**: ドロップ後に個体同士が重ならない。棚外に出ない

UI と感触は自動テストの対象外とし、実ブラウザでの実プレイで評価する（29 章）。
